## 2024-05-18 - Avoid loading full tables into memory for aggregate analytics
**Learning:** `analytics_overview` initially pulled entire `users`, `documents`, `messages`, and `auth_sessions` tables into Python memory using `fetch_all`, then applied O(N) date-filtering and aggregation logic in list comprehensions. For even moderate loads, this severely impacted memory and execution time.
**Action:** Push aggregate calculation and timestamp filtering down to the database layer using `COUNT(*)` and parameterized subqueries in `fetch_one`. Use `settings.using_postgres` for correct timezone-aware ISO format parsing versus string formats (SQLite).
